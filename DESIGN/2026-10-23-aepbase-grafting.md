# History Grafting and Integration of `aepbase`

* **Date**: 2026-10-23
* **Status**: Completed

## 1. Overview

This document records the grafting of [`aepbase`](https://github.com/rambleraptor/aepbase) into `aep-monorepo` while preserving all 90 historical Git commits and line-by-line attribution.

---

## 2. Source Repository Metadata

* **Source Repository**: `https://github.com/rambleraptor/aepbase` (branch `main`)
* **Target Monorepo Subdirectory**: `aepbase/`
* **Historical Commits Imported**: 90 commits (through `0001945`)
* **Module Path**: `github.com/rambleraptor/aepbase` → `github.com/aep-dev/aep-monorepo/aepbase`
* **Language/Framework**: Go 1.25, SQLite (`ncruces/go-sqlite3`, WASM-based, no cgo); Astro marketing site in `aepbase/website/`

---

## 3. Graft Methodology

The graft followed the procedure in [2026-08-16-repository-initialization-and-grafting.md](2026-08-16-repository-initialization-and-grafting.md):

1. Clone source repository:
   ```bash
   git clone --branch main --single-branch https://github.com/rambleraptor/aepbase.git /tmp/aepbase-graft
   cd /tmp/aepbase-graft
   ```
2. Rewrite subdirectory paths:
   ```bash
   git-filter-repo --to-subdirectory-filter aepbase
   ```
3. Add temporary remote and merge:
   ```bash
   git remote add tmp-graft-aepbase /tmp/aepbase-graft
   git fetch tmp-graft-aepbase
   git merge tmp-graft-aepbase/main --allow-unrelated-histories -m "graft: import aepbase with rewritten path history" --no-edit
   git remote remove tmp-graft-aepbase
   ```

## 4. Post-Graft Integration

* **Module path**: Renamed to `github.com/aep-dev/aep-monorepo/aepbase`, and imports of `github.com/aep-dev/aep-lib-go` now point to the in-repo `github.com/aep-dev/aep-monorepo/aep-lib-go`.
* **Go workspace**: `./aepbase` is added to [go.work](../go.work).
* **Dependency sync**: `aepbase` is listed in `DEPENDENT_MODULES` in [scripts/sync-deps.py](../scripts/sync-deps.py) so that `just fix` / `just check` keep its `aep-lib-go` requirement current.

---

## 5. Bazel Target Architecture

`BUILD.bazel` files are generated by Gazelle. `aepbase/website` is excluded from Gazelle.

* `//aepbase:aepbase`: The aepbase server binary.
* `//aepbase/examples/bookstore:bookstore`: The bookstore example server with custom methods.
* `//aepbase/pkg/...`: Library packages; tests in `//aepbase/pkg/aepbase:aepbase_test` and `//aepbase/pkg/cel2sql:cel2sql_test`.

aepbase's dependencies (`ncruces/go-sqlite3`, `golang.org/x/crypto`, newer `golang.org/x/sys` and `golang.org/x/text`) require Go 1.25. The Bazel Go SDK was upgraded to 1.25.5 (with `rules_go` 0.57.0 and `gazelle` 0.45.0) ahead of the graft.

---

## 6. CI/CD Workflows

The standalone repository's `ci.yml`, `e2e-validator.yml`, and `openapi-lint.yml` workflows are consolidated into [`.github/workflows/aepbase-ci.yml`](../.github/workflows/aepbase-ci.yml), triggered on changes under `aepbase/`:

* **test**: `bazel test //aepbase/...`
* **bookstore-demo**: Runs `examples/bookstore/demo.sh` against the bookstore server, using the in-repo `aepcli`.
* **e2e-validator**: Validates aepbase-served resources with the in-repo `aep-e2e-validator`.
* **openapi-lint**: Lints the generated OpenAPI spec with Spectral and `@aep_dev/aep-openapi-linter`.

Binaries are built with Bazel instead of `go install ...@latest`, so CI always exercises the current monorepo versions of `aepcli` and `aep-e2e-validator`.
